# Contributing

## Prerequisites

- **Bun 1.4** — package scripts, tests, and tooling.
- **Rust 1.99** — via `rust-toolchain.toml` (kept in sync with
  `[workspace.package].rust-version`).
- **cargo-deny** for the supply-chain check (`cargo install cargo-deny`).
- **Tauri Linux prerequisites** — only needed on Linux:

  ```bash
  sudo apt install libwebkit2gtk-4.1-dev libxdo-dev \
    libayatana-appindicator3-dev librsvg2-dev
  ```

## Repository layout

```text
apps/desktop/       Tauri 2 desktop shell — React frontend and the ovo-desktop
                    bin crate under src-tauri/
packages/ovo/       @qntx/ovo — platform-neutral TypeScript SDK; builds with vp pack
crates/             ovo-* Rust crates of the agent harness (lands per milestone)
scripts/            repository checks (version lockstep, licenses, stray d.ts)
docs/               public documentation mirrored to docs.qntx.org
```

## Local gate

Run before opening a pull request:

```bash
bun run lint && bun run typecheck && bun run build && bun run test
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
cargo deny check
```

`bun run dev` starts the desktop app in Tauri dev mode; `bun run bundle`
produces the platform installer.

## Frontend bindings

The frontend talks to Rust only through typed commands in
`apps/desktop/src/bindings.gen.ts`, generated by tauri-specta. After changing a
command signature, regenerate with:

```bash
OVO_UPDATE_BINDINGS=1 cargo test -p ovo-desktop bindings_are_current
```

Never edit `bindings.gen.ts` by hand; `cargo test` fails when it drifts.

## Versioning and release

`@qntx/ovo` and the Cargo workspace share one lockstep version. `bun run release`
runs `bumpp` (`bump.config.ts`), which bumps `packages/ovo/package.json` and the
Cargo workspace version together, refreshes `Cargo.lock`, and opens a
`release/v<version>` pull request. `scripts/check-version.ts` (part of `bun run
lint`) guards against drift: every published package version must equal
`[workspace.package].version`, every workspace member crate inherits
`version.workspace = true`, internal `crates/` path dependencies must pin
`=<version>`, and the version string may appear nowhere else in `Cargo.toml`.

## Commits

English Conventional Commits: `type(scope): subject` (`feat`, `fix`, `docs`,
`style`, `refactor`, `perf`, `test`, `chore`, `ci`, `build`, `revert`), subject
in imperative mood, no period, ≤ 50 chars; `BREAKING CHANGE:` footer for
breaking changes.

## Documentation policy

`docs/` is public documentation mirrored to docs.qntx.org. `docs/internal/` is
local-only design material and must never be committed.

## Upstream reference checkout

The design docs and parity tooling pin upstream pi at v1.5.0. For local
auditing and the `check.ts --upstream` mode, keep a read-only checkout under
`3rdparty/` (gitignored):

```bash
git clone --branch v1.5.0 https://github.com/earendil-works/pi 3rdparty/pi
```

It is a reference only: never build, install, or commit it.
